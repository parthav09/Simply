## Separate landing experience and lab workspace

The landing page now has a cream and forest-green editorial design, with an original isometric store scene instead of the embedded lab. `RecordedShowcase` reads the same integrity-checked published recording and loops its event cursor automatically. ## Unified theme and responsiveness

The independent green, purple and slate page palettes have been replaced with one semantic token system in `styles/tokens.css`. Shared control, type, spacing, surface, state, focus and map tokens support light, dark and system appearance. Page styles define composition rather than overriding the palette. Legacy stylesheets were removed; the root stylesheet is the single CSS entry point. Theme preference persists across routes and refreshes.

Verified recordings are shared through a bounded cache with integrity and source-identity checks. Exports invalidate the catalogue. Replay seeking uses indexed shopper histories instead of rebuilding all preceding events. Static map fixtures are memoized, and live waiting-clock updates do not rerender the whole replay workspace. Live catalogue polling pauses in hidden pages and backs off when disconnected. The unavailable-service state offers saved replays rather than an indefinite loading message.

Validation: all 126 Python/architecture tests, type checks, lint, production build, replay/live contracts and four full-trip replay/report checks pass. Added UI checks cover request coalescing, integrity rejection, retry, catalogue invalidation, indexed seeking, and WCAG AA normal-text contrast for both themes. A local benchmark of 200 seeks in the 942-event recording measured roughly 66–72 ms for repeated full-history scans and 0.6 ms for indexed projection. This is projection CPU time, not end-to-end UI speed or model latency.
